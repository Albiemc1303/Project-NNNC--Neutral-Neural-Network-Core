## II.1 Native general protected authorization — adopted C1

For x:GX, g:GG, p:PRINC, h:GH, B:Fin(BASIS), define:

```text
GeneralConstitutionallyAuthorized(x,g,p,h,B) iff
    P1.EffectiveGovernance(h,x)=Some(g)
    and P1.PriorValidAuth(x,g)
    and Authenticated(p,x,g,h)
    and EffectsCovered(x,h,B)
    and BasisValidBefore(x,h,B)
    and RequiredLifecycleChecks(x,h,B)
    and ConstitutionalRulesSatisfied(x,g,p,h,B).
```

Authenticated binds the actual principal of x. P1.PriorValidAuth retains all applicable prior approval/execution/P0-policy conditions. Any additional propose/certify/separation requirements come from that prior policy. Roles are distinguished; distinct holders are not invented. Holding competence, resources, custody or a preserved identity verdict supplies none of these conjuncts.

For every mutation actually implemented by the reference transition system, required effects are derived from the operation payload before guard evaluation: revocation entails ADMIN/Protected/AuthorityRevocation; adoption entails ADMIN/Protected/ConstitutionalChange; supported role/competence deltas entail the corresponding structural effect. Event.effects contains supplemental observations, not the sole exhaustive authority-effect inventory. Omitted tags cannot hide an implemented mutation. A known affected scope outside the declared covered scopes prevents authorization.

EffectsCovered requires a complete finite relevant effect-to-scope inventory with every scope represented by its own validated BASIS. For scope-governed acts B must be nonempty. Each scope's cv must be adopted and governing immediately before commit; policy is the actual P0–1 policy, not an alias for cv. A lifecycle basis additionally links the unchanged P2.V used for its inherited checks. Different scoped CV/policy values are permitted only with independently established applicable composition; neither existential validation of one scope nor repeated calls with arbitrary v values establish it. The executable reference model implements the conservative common-cv/common-policy case; unsupported divergent composition gives UNDETERMINED, not permission.

RequiredLifecycleChecks is effect-driven. If x affects a P2 locus/lifecycle obligation, every such obligation must have an established LifecycleLinks witness and its P2.AuthorizedTransition call, with x2,l,h2,v passed unchanged. It is not sufficient to label an event ADMIN. A non-lifecycle administrative operation uses P0/P1 prior authority without inventing any suspension locus. If the effect inventory cannot establish which case applies, positive authorization is unavailable.

The guard is evaluated on actual prior state. A pending guard forecast may use the current snapshot as a prediction, but actual commitment must re-evaluate at the real strict precommit prefix. No authorization created by x or a later event may validate x. The reference model uses exactly the same protected guard for its forecasts and commit-time replay.

## II.3 Evidence table and complete outcome mapping

CommitAssessment returns COMMITTED for CommitEvidence=TRUE and PendingEvidence=FALSE; PENDING for CommitEvidence=FALSE, PendingEvidence=TRUE and HistoryCoverage=TRUE; UNKNOWN otherwise. In particular contradictory commit/pending evidence and no affirmative state evidence are UNKNOWN. Diagnostics retain the contradiction. Actual committed effects and recognition of legitimate authority are separate: a physically committed unauthorized event is recorded, never erased because it lacked authority.

AuthorizationEvidence assesses the complete guard under a settled applicable basis. Missing required ordering, unknown material scope coverage or incompatible unresolved governing versions gives UNKNOWN; a settled failed authorization under a known governing basis is FALSE. Unknown is not a negative truth claim. Then AuthAssessment follows this exhaustive mapping:

| State | Authorization evidence | Outcome |
|---|---|---|
| PENDING | TRUE | PERMITTED_TO_COMMIT, forecast only |
| PENDING | FALSE | BLOCKED |
| COMMITTED | TRUE | COMMITTED_WITH_VALID_AUTHORIZATION |
| COMMITTED | FALSE | COMMITTED_WITHOUT_VALID_AUTHORIZATION |
| PENDING or COMMITTED | UNKNOWN | UNDETERMINED |
| UNKNOWN | any | UNDETERMINED |

An established revocation before commit produces BLOCKED for a pending act or the explicit committed nonconformance for an actual act. Later uncertainty cannot soften an already established false precommit authorization. Conversely a disputed alleged revocation is not a settled failure. The reference records actual events and separately marks protected violations; it does not recognize invalid events as legitimate governance updates.

## II.4 Causal history versus authority history

GH is the P1 recognized authority sequence. A P2 causal history is projected only for a lifecycle linkage. A finite lifecycle bridge must give: an injective occurrence correspondence on the relevant events; a P2 strict partial causal order; a separately supplied adjudicated authority sequence compatible with known causal edges; correspondence of the event's strict authority prefix, governance and observation cut. Missing causal edges do not imply concurrency. A compatible linearization alone does not prove its authority; that remains the explicit P0/P1 ordering contract.

The reference model stores an authority-event tuple and a separate causal-edge set. Prefix extraction uses the tuple, rejects duplicate occurrence IDs and reversed/foreign causal edges, and replays only preceding events. Causal relations are never defined as sequence order. Real distributed reconciliation/fencing remains a P0-O03/O07 obligation. No arbitrary partition's preferred sequence acquires authority from this model.

# Part III — Precedence, conflict and satisfiability

## III.1 Normalized conflict

Eligibility requires an accepted in-force source, applicability in the same relevant decision/scope, and a valid governing version. A proposed/unadopted rival is excluded; an unsupported assertion alone cannot freeze valid governance. Own exceptions and limits are normalized inside the requirement before conflict assessment. The finite normal form uses a nonempty universe U of mutually exclusive decision outcomes. DUTY(A) restricts admissible outcomes to A; PROHIBITION(A) excludes A; PERMISSION(A) guarantees that the specified alternatives A remain available, but does not require any to be selected. Two restrictions conflict if their jointly allowed set is empty. A permission conflicts with a restriction when some positively permitted alternative is excluded by that restriction. Two permissions alone do not conflict. These are explicit **positive permission** semantics for this finite interpretation, not an assertion that every natural-language MAY is already normalized this way. Weak permissions and own exceptions must be distinguished by the interpretation contract; unsupported normalization cannot yield a positive conclusion.

## H.2 Proof arguments for the restricted contract class

These are explicit mathematical arguments, not machine-checked theorem-prover results. They rely on truthful interpretation of imported contracts, complete effect/semantic/provenance inventories where declared, a fixed normalized finite rule language, and an externally grounded adjudicated authority sequence. Finite tests independently exercise representative instances of the arguments; neither replaces source-contract verification.

**L1 — Well-founded adoption.** At prefix rank 0 no ordinary adoption can cite a smaller event prefix; only externally grounded roots can enter. Suppose the claim holds below rank n. A valid ordinary event at rank n cites an already adopted parent at a smaller prefix and introduces a fresh identifier. Its parent chain is therefore finite and rooted by the induction hypothesis. Freshness prevents adding an edge back to an existing ancestor or root. Appending another event cannot change that child's fixed parent. Consequently admitted ordinary lineage is finite, single-parent and acyclic. A registry of proposed unadopted versions does not establish applicability.

**L2 — No same-step self-authorization.** The replay applies an event only after its protected guard and amendment checks are evaluated in the state produced by preceding events. New rules/grants/versions are not installed until after those checks. AuthRules is computed from prior roots/dependencies and every changed relied-upon semantic key or dependency source is rejected. Thus neither a successor's new grant nor a changed authorizing rule can satisfy the current event's guard. Delta may be inspected for admissibility without supplying its own authority.

**L3 — Lifecycle conservativity.** ConstitutionallyAuthorized is a conjunction including unchanged P2.AuthorizedTransition through a fixed same-occurrence/locus/history/version correspondence. A false inherited conjunct forces the whole relation false. General authorization also dispatches to all effect-required lifecycle checks, so choosing an administrative label cannot suppress one. This proof requires complete trustworthy effect/link inventory; when that inventory is unknown the assessment cannot be TRUE.

**L4 — Historical preservation.** State.records is an immutable tuple and every apply operation returns old records followed by exactly one new event classification. Adopted versions and their origins are immutable and only fresh valid successors are appended. Induction over replay length gives old records as an exact prefix. Established invalid committed attempts are appended and marked as violations, while UNDETERMINED events are appended to a separate unresolved-protected-event register; neither can update governing authority without positive authorization. Later adoption/reversion therefore cannot erase or retroactively legitimate them. This is logical append-only behavior, not durable storage proof.

**L5 — Conservative conflict resolution.** RESOLVED is returned only after complete material inputs, no controlling predecessor conflict, no defeat-graph cycle, and one direct dominator of all other members. Its returned identifier is selected from S and every other disposition carries None. Hence the algorithm cannot fabricate a winner outside S or resolve a cyclic/incomparable group by identifier order. The defeat relation itself need not be transitive; requiring it globally would contradict admissible unresolved examples. Joint satisfiability is separately checked.

**L6 — Independence soundness relative to the finite provenance contract.** ESTABLISHED requires evaluator separation on actual actor-equivalence classes and complete transitive control evidence. Every decisive material relied-upon observation must have valid closed ancestry; an absent ancestor or cycle prevents success. At least one actually material leaf-source contribution must be external to candidate control. Adding a nonmaterial external observation cannot affect that material closure and therefore cannot convert candidate-only support into ESTABLISHED. PASS additionally requires all profile/domain/criterion/binding/authority conditions. The conclusion depends on the supplied materiality/validity/control interpretation; it is not empirical certification of real actors.

**L7 — Scoped non-escalation and cumulative bounds.** Authorization requires a valid prior basis and grants for every affected scope. No existential single-scope witness can cover another scope. In the implemented common-policy case any missing/divergent basis is unresolved. An ordinary amendment must use the prior governing common parent; concurrent siblings may govern distinct scopes, while a stale overlapping sibling cannot update an already changed scope. Development compares the cumulative result with the adopted baseline, so individually small steps cannot evade its bound.

Unsupported semantic values, unknown keys or effect tags cannot be positively authorized/validated by assuming a general equivalence oracle. Complete actor/materiality/authority inputs are explicit fixture assumptions.
